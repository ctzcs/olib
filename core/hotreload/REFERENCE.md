# 热重载参考

[README](README.md) 的补充细节：配置、外部构建、与其他模块的配合、模板结构。

## Watch 的配置要点

- `command` 是参数数组，直接传给进程，不经过 shell；`{output}` 会被替换成本次唯一的产物路径。
  命令必须完整生成一个 DLL，且成功返回后不能继续后台写产物。
- `roots`（目录或单个文件）按 `working_directory` 解析。默认只递归监听 `.odin`，忽略隐藏目录、`build`、`Library`，
  不跟随符号链接。`#load` 的数据文件和额外 import 根要放进 `roots` 或 `extensions`；不会自动解析整个依赖图。
- 扫描在后台低优先级线程进行，`watch_update` 每帧只读取结果。每隔 `poll_seconds` 列一遍目录，比较大小和修改时间，
  只读取新增或元数据变化的文件，所以读多少内容只取决于改了什么；列目录的耗时随文件数增长（Windows 每项约 2 µs）。
  最终仍按内容哈希判断，只 touch 不会重编；读取时修改时间离当时不足 3 秒的文件，下次再按内容复核，覆盖 FAT/HFS+ 的粗时间戳。
  Windows 用 `FindFirstFileW` 随目录项取元数据，读文件时允许其他进程删除或改名，不会让编辑器保存失败。
- 文件很多时，完整扫描的间隔自动拉长到其耗时的 10 倍，后台最多占约一成单核；最近 30 秒改过的文件（最多 64 个）
  在两次完整扫描之间单独检查，连续编辑同一批文件仍及时生效。`roots` 仍只放编译输入，不放与 DLL 无关的资产目录。
- 编译结束后先等一次在其后开始的完整扫描，确认产物不是过期源码编出来的，再进入 Ready。
- `mode = .Manual` 不扫描源码：启动时编译一次，之后调用 `watch_retry`，或修改 `trigger_file`（每 `poll_seconds`
  查一次修改时间）才编译。适合用编辑器任务/快捷键触发，或想要零后台开销的超大项目；编译中再次触发会丢弃这次结果并重编。
- 只有一个后台编译任务，连续编辑会合并；内容不变的失败不会每帧重编。修复源码后自动重试，
  修复环境后可调用 `watch_retry`。
- `watch_apply(..., .Migrate/.Reset)` 在 Ready 时指定策略；若此前已被拒绝，先 `watch_retry` 再应用。
- `dispose` 会等待正在运行的编译任务，编译器挂起时退出也会等待；暂无取消或超时 API。

## 外部构建系统、缓存和产物

已有构建系统可跳过 Watch，对**已写完**的产物直接调用 `reload(&session, path)`；Session 只复制产物，不监听该路径。
影子文件与原产物在同目录，源文件不会被 Windows 长期锁住；运行依赖的 DLL 仍需在宿主/系统可搜索的位置。
`cache_parent` 可指定构建缓存父目录；多个宿主会话使用独立缓存，退出时清理自己的产物，崩溃留下的临时文件不会自动清理。
这些隔离目录是[生成文件规则](../../prompts/new-project.md#生成文件与目录纪律)的生命周期例外，不要合并成共享输出目录；
需留存的诊断副本在会话停止后放入所属项目的 `library/tmp`，验收截图放 `library/screenshots`。

## 与 UI、Foster、资源的配合

- **UI**：每个候选新建一个地址稳定的 `UI_Context`，在 `load` 里 `ui_init` 并重新注册字体，在 `unload` 里先 `ui_dispose`
  再释放它引用的字体/纹理。旧 Context 不跨 DLL 复用（Clay 保存回调和文字地址），UI 声明每帧在新模块里重新执行。
  `kit/ui` 不需要另一套声明接口。
- **交互状态**：背包是否打开、选中道具、设置值等可进快照；悬停、按住、拖动、键盘焦点等瞬时状态默认重置，
  编辑事务在旧模块卸载前取消或完成。纯 UI 样式改动也会重建整个模块实例，只保留你写进快照的状态。
- **资源和全局状态**：外部资源由宿主持有并通过稳定服务获取，模块引用不能超过宿主资源寿命。
  同一个包分别编进 EXE 和 DLL 会各有一份全局变量（资源导入器注册表、Clay 当前上下文等），
  不要把包全局状态当成跨模块共享服务。编译监听器放在宿主，避免模块卸载时仍有编译任务。
- **GPU**：Batcher、UI 文本和帧临时数据用完才能切换；异步 GPU/资源释放由宿主建立同步点，库的纯 core 层不替代设备同步。
- **字体与分辨率**：仍按[最终像素采样约定](../../kit/ui/README.md#最终像素采样与清晰度验收)绘制，热重载不改变这些策略，
  游戏资源热更新也不等同于代码热更新。
- **Shader**：HLSL 继续走 `kit/rendering/shader/dev`；宿主里的 Shader 编译和游戏编译通过 `core/devbuild` 串行启动子进程，
  避开 Odin `process_start` 的句柄继承并发问题，游戏帧不等待这个锁。

## 模板的目录与失败提示

模板用 core（游戏）、core_editor（编辑器实现）、editor（常驻开发入口）、game（发布入口）四个目录：

- `src/core_editor/module.odin` 把编辑会话和共享 core 组装成一个 DLL，游戏逻辑、游戏 UI 和编辑器 UI 一起热重载。
- `src/editor/main.odin` 保留窗口、资源、监听和最小失败提示；共享服务协议和资源函数在 `src/core/services.odin`，没有独立 host 包。
- 组合快照保存游戏进度、编辑会话的持久数据和待处理命令；UI/GPU 对象和瞬时输入重新建立，旧的按住输入要等松开再接收。
- `game` 静态导入 `core`，发布时排除 `core_editor`、`editor` 和加载器；入口或共享服务协议改动后重启，
  常驻入口不创建静态游戏实例，也不持有 DLL 内的业务指针。
- 失败摘要显示在窗口内，完整日志写入 `build/hotreload-last-error.txt`；首次编译失败也能显示，旧模块仍运行时显示版本号。
  提示在等待/编译期间保留，只有成功安装新模块才清除。这是模板接入代码，`core` 层只返回状态和诊断，已有项目要自行接入。

实现只依赖 Odin 标准库和 `core/devbuild`，所以放在 `core/hotreload`，不另做 Foster 生命周期封装。
