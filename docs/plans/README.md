# 计划（docs/plans）

这里放交给 AI（Claude、GPT 等）或人执行的多步改动计划。

- `docs/plans/*.md`：**进行中**的计划。
- `docs/plans/archive/*.md`：**已完成**或**已放弃**的计划，只作历史记录。

## 归档规则（执行者必须遵守）

计划的最后一个 commit 完成、验收通过后，**执行者在同一分支上立即归档**，不需要等用户提醒：

1. `git mv docs/plans/<name>.md docs/plans/archive/<name>.md`（用 `git mv`，保留重命名历史）。
2. 在文件标题行下面插入状态块，正文一字不改：

   ```markdown
   > **状态：已完成（YYYY-MM-DD）** · 提交 `<第一个 commit>`..`<最后一个 commit>`
   > 偏离：<与计划不一致的地方及原因；没有就写“无”>
   ```

   放弃的计划写 `**状态：已放弃（YYYY-MM-DD）**`，并用一句话说明原因。
3. 单独提交：`docs: 归档计划 <name>`。
4. 汇报里说明计划已归档。

例外：用户明确说计划还要继续（例如分阶段执行、只做了其中几步）时，不归档；在文件标题下写 `> **状态：进行中** · 已完成第 N 步`。

## 写新计划时

- 文件名用短横线小写英文：`<主题>.md`，例如 `temp-allocator-and-vet.md`。
- 结构参考归档里的计划：背景 → 已定决策 → 执行步骤（每步一个 commit）→ 验收 → 禁止事项 → 汇报内容。
- 执行步骤的**最后一步固定为“按 docs/plans/README.md 归档本计划”**。
- 不改 `archive/` 里的历史计划正文；新的决定写进新计划。
