# olib 编辑工具开发约定

本文件约定使用 olib 开发编辑器、游戏内开发面板和交互工具时的组织方式。适用于对象变换、曲线、刷子、配置编辑等工具，不绑定某种场景模型；工具 UI 默认用 odin-imgui（见第 1 节），本文规则本身不依赖具体 UI 库。核心规则是：**编辑会话统一管理，工具负责交互，修改通过编辑事务进入文档。**

工程创建见 [新项目创建提示词](new-project.md)，包依赖和模拟数据规则见 [面向数据开发约定](dod-guidelines.md) 第 2 节。本文是工具交互与编辑事务规则的唯一来源；其他文档只维护入口和所属领域的边界。

本文描述项目应实现的职责，不代表 olib 已提供编辑器框架、事务 API 或 `kit/editor` 包。下文文件名、`Editor_State` 等类型名均为推荐名称。按实际需求创建文件，不预建空包、插件系统或通用反射命令系统。

## 1. 目录与接入

项目专用 Editor 的实现放 `src/core_editor/`，与游戏代码 core 一起构建为一个 DLL；开发入口 `src/editor/main.odin` 是薄常驻 App，只管理窗口、资源、监听、切换和最小失败提示。入口与实现各有明确职责，不再增加 host、editor/play、src/tools/editor 或转发启动目录。普通工具文件随 DLL 热重载，不要求逐函数导出；入口、core/services.odin 的共享服务协议/资源函数或依赖库修改后重启。只有确需其他独立工具进程时，才增加 src/tools/<name>。

```text
src/core_editor/         package core_editor，可热替换的编辑器实现
    module.odin         DLL 接入，组装 core 与编辑器，组合会话快照
    editor.odin         会话、工具切换、输入分配、生命周期
    document.odin       编辑文档、载入保存、未保存状态
    history.odin        编辑事务、撤销重做
    viewport.odin       编辑相机、坐标转换、辅助绘制
    transform_tool.odin 对象变换工具，按需接入 kit/gizmo
    <name>_tool.odin    其他实际需要的工具

src/editor/             package main，薄常驻开发入口
    main.odin           App、资源、监听、DLL 切换与失败提示
src/core/services.odin  共享服务协议与资源函数，游戏和开发入口共用
src/tools/<name>/       确需其他独立工具进程时才创建（package main）
    main.odin

tools/                  无界面的构建、转换、校验、生成和打包入口
```

这是职责划分，不是必须建立的文件清单。小编辑器可合并文件；需要独立依赖边界或实际复用时再拆子包。编码遵循 [CODE_STYLE](../docs/CODE_STYLE.md) 第 2～5 节。

编辑器、开发面板和交互工具的 UI 默认用 `thirdparty/odin-imgui`（Foster 后端），玩家 UI 用 kit/ui；ImGui 上下文归 core_editor DLL，接入方式见[新项目约定的 UI 一节](new-project.md#ui-用什么以及如何接入)和模板 `core_editor/editor.odin`。

包依赖遵循 [dod-guidelines 第 2 节](dod-guidelines.md#2-包与依赖方向)。精简模板的 `core`（及按需在 core 内拆出的 `def / data / logic / view` 子包）不 import core_editor、editor 及其子包，装载器不反向依赖编辑器。开发入口动态加载 core_editor DLL；发布构建须通过独立入口或编译期文件选择排除编辑器及仅供开发的 UI 依赖，不能只用运行时开关隐藏面板。只读调试面板不需要文档和撤销系统，但仍遵守输入与生命周期约定。

## 2. 状态与所有权

| 状态 | 所有者与边界 |
| --- | --- |
| 可保存的对象、路径、配置等内容 | 编辑文档，复用项目的数据格式；不是工具的私有副本 |
| 当前文档、选中对象、当前工具、活动事务与历史 | 编辑会话（如 `Editor_State`）；历史与对应文档绑定 |
| 编辑相机、视口范围、悬停信息 | 编辑视口，不写入游戏内容 |
| 拖动起点、操作阶段、临时预览 | 工具的跨帧状态，退出或取消时清理 |
| 试玩产生的模拟状态 | 独立模拟实例，按模拟层规则维护 |

- 编辑器 DLL 拥有游戏与编辑会话，组合快照保留权威游戏状态、会话持久数据和待处理命令，候选恢复使用独立内存，失败不能改变旧实例。UI（Clay、ImGui 上下文）/GPU 对象与输入捕获不进入快照，ImGui 布局等编辑器偏好以纯文本随会话快照保留；成功切换时重建并屏蔽按住输入直到松开。接入文档/历史后也必须保存，活动事务先在安全边界完成或取消，再制作快照。
- 会话创建、持有并释放自己的状态，显式传参，不散布可变全局单例。一个视口通常只需一份当前工具交互状态，不给每个场景对象分配一份 gizmo。
- 跨帧引用使用稳定 ID 或带有效性检查的句柄。不能保存可能因扩容或删除失效的指针、行号；操作目标在开始时绑定，后续选中变化不能把操作转移给新对象。
- 文档只保存内容，选中、悬停、工具临时状态与撤销历史不混入内容文件。编辑器布局等偏好如需持久化，使用独立的编辑器设置。
- 试玩从文档创建独立模拟实例；含动态数组等堆数据时必须独立复制，并写明分配和释放责任。运行结果默认不写回文档，需要时提供明确的应用操作并走编辑事务。
- 调试运行状态通过明确的调试命令进入规则函数（精简模板的 `core/rules.odin`，拆包后为 `logic`），遵守模拟修改规则；它不自动修改源内容或获得内容编辑器的撤销能力。配置类型、装载器与语义校验复用项目已有实现，不维护第二份玩法规则。

## 3. 工具生命周期与输入

所有交互工具遵循：激活 → 接收输入 → 开始操作 → 持续更新 → 提交或取消 → 退出。具体 proc 名不强制一致；起步使用工具枚举加 `switch` 分发，只有实际需要动态扩展时才设计注册机制。

- 工具接收编辑器整理后的输入和视口上下文，不自行读取全局鼠标与快捷键。属性面板、快捷键和视口工具共用编辑会话的操作入口。
- 无捕获时先判断 UI、键盘焦点和视口归属，再分配给当前工具；文本输入期间不能把普通编辑快捷键误发给场景工具。使用 ImGui 时以 `WantCaptureMouse`、`WantTextInput` 作为 UI 归属依据；重载、切换或离焦后仍按住的鼠标用 `ConfigFlags.NoMouse` 屏蔽到松开；不开键盘导航，除非已明确分配键盘焦点，避免同一按键被面板和视口同时处理。
- 操作开始后明确捕获相关输入，由该工具持续接收直到结束。对象选择和相机导航也参与同一套分配；一次鼠标操作不能同时触发多个消费者。
- 鼠标移出视口或经过 UI 时，已有捕获仍要收到移动、松开和取消。停用、离焦等收尾事件也必须送达，不能因不再绘制工具就跳过更新。
- 切换工具或文档、删除操作目标、关闭视口、窗口离焦时，默认取消未完成事务，再清理状态。取消必须在旧文档和目标仍可恢复时完成；外部变化已使目标失效时安全结束，不向复用的 ID 或句柄写回，并使不再适用的历史失效。
- 同一文档起步只允许一个活动修改事务。遇到另一个修改、撤销重做、保存或试玩请求，先明确完成或取消当前事务，再执行请求，不隐式交错。普通只读查询不受限制。

## 4. 编辑事务与撤销

**一次用户操作对应一次事务，可以持续多帧并修改多个对象。所有可保存的内容修改都经过事务，包括视口工具、属性面板和菜单操作。** 文档载入或整体替换是明确的生命周期操作，须重置或重新绑定历史，不能留下指向旧文档的记录。

| 阶段 | 必须完成的事 |
| --- | --- |
| 开始 | 绑定文档和目标，记录恢复所需的修改前数据 |
| 更新 | 校验并应用当前修改，同步文档与预览；拒绝时保留上一份有效状态 |
| 提交 | 有实际内容变化才生成一条撤销记录，并清除已不适用的重做分支 |
| 取消 | 恢复开始前的数据，不新增历史，不清空原有重做分支 |

- 一次连续拖动只生成一条历史；多个目标、关联切线或刷过的一批格子属于同一操作时一并提交或恢复。开始后没有变化，或最终回到原值，不生成空记录。
- 不要求每次修改排队，也不要求为每个字段生成 setter。允许直接调用带类型的编辑函数；同一种修改从面板或工具发起时复用校验和应用逻辑。
- 原子性以一次操作为单位：校验失败不能留下半份多对象修改。恢复过程不能简单重新执行一条可能被当前规则拒绝的普通用户命令；要有能够恢复完整有效状态的路径。
- 小文档可保存修改前后的完整快照；大文档按需要记录差异。含堆数据时不能用浅复制冒充快照；记录自己的所有权、历史淘汰和文档关闭时的释放责任。
- 开始、更新和结束可能在同一帧发生。处理顺序必须保留修改前的值，应用最后一次有效更新后再提交；取消优先于提交。

## 5. 变化传播、保存与试玩

- 正常编辑、取消恢复、撤销和重做走统一的数据变化入口，维护相同的版本号、变化记录和派生数据刷新。不能只恢复字段而遗漏空间索引、预览网格或 GPU 缓存。
- 文档是权威内容，缓存只派生自文档。读取前保证派生结果有效；需要耗时重建时明确显示过期状态并安排重建，不能让旧结果冒充当前内容。
- 未保存状态依据当前可保存内容与最近一次成功保存的内容是否一致判断。可以用历史保存点辅助追踪，但单调递增的版本号或历史条数不等于内容相等；撤销回保存状态、取消操作以及历史分支变化都要正确处理。
- 保存前处理活动事务并校验文档，成功后才更新保存基准。保存失败保留旧文件和未保存状态，返回可定位的错误；按平台采用临时文件与安全替换等策略，避免失败写坏唯一文件。
- 载入失败保留当前有效文档；载入成功后重置选中、工具临时状态和旧历史。关闭或替换有未保存内容的文档时，明确提供保存、放弃或取消操作。
- 试玩和导出使用已明确接受的内容版本；从模拟应用修改回文档时，仍需校验并形成可撤销的编辑操作。

## 6. 视口与辅助绘制

- 场景内容走场景渲染；手柄、辅助线和编辑 UI 按最终输出像素绘制。顺序为场景 → 缩放/后处理 → 视口辅助图形 → 面板/UI，不把工具覆盖层随低分辨率场景一起放大。
- 明确区分世界、窗口逻辑和最终 drawable 坐标。输入在边界统一转换；鼠标与 viewport 使用相同的最终像素坐标，保留非零视口偏移。相机视口尺寸与绘制视口匹配，resize 或 DPI 变化同步更新。
- 辅助图形裁剪到所属视口，绘制调用所需的矩阵、材质和裁剪状态由视口接入代码设置；工具不能泄漏绘制状态影响后续 UI。
- 用实际接受的数据绘制工具；修改被修正或拒绝后，不能仍把未经接受的位置画成已生效的结果。临时候选预览必须与已生效内容有明确区别。
- 字体、截图和多尺寸检查遵循 [UI 像素与采样约定](../kit/ui/README.md#最终像素采样与清晰度验收)。截图读取最终输出；3D 抗锯齿和字体小字号质量分别验收。

## 7. 现有 gizmo 的接入

`kit/gizmo` 负责手柄交互与绘制，不识别项目对象、不修改文档、不保存文件。二维使用 `transform2d_update / geometry / draw`，三维使用 `transform_update / geometry / draw`；真实参数与限制见 [Gizmo 文档](../kit/gizmo/README.md)。

| gizmo 返回值 | 项目接入行为 |
| --- | --- |
| `started` | 用更新前的文档值开始事务，绑定目标 ID |
| `changed` | 将返回的变换交给编辑修改入口 |
| `cancelled` | 取消事务，恢复修改前的数据，优先于 `ended` 的提交处理 |
| `ended` 且未取消 | 提交一次编辑，忽略无实际变化的操作 |
| `captured` | 阻止其他鼠标消费者处理本次输入，包括释放帧 |

`allow_start=false` 只阻止开始，不截断已经捕获的操作；必须持续调用 update，包括释放与离焦帧。对象切换由接入方显式传 `cancel`。当前 gizmo 的取消只报告中断，不自动恢复已经接受的变换，回滚由编辑事务完成。处理中断后仍按 gizmo 的 `captured` 结果维持输入归属到松开，避免同一次按住转交给新工具。

应用结果后重新读取实际接受的变换，再计算 geometry 并绘制。具体工具可以组合 gizmo（例如操作某个控制点），修改关联数据和历史仍由该工具的事务负责。本文不新增 gizmo API，也不要求项目采用 gizmo 的变换类型作为存档类型。

## 8. 通用能力的提取边界

- 通用且无运行时依赖的数据和算法适合进入 `core`；通用交互与渲染能力适合进入 `kit`，遵守已有的 foster/kit 边界。
- 项目对象 ID、业务校验、文档格式和具体工具留在项目中。库包不能 import 游戏代码或假设项目必须采用某种场景对象结构。
- 先在实际工具中验证职责和 API，再按实际复用提取。新增工具不等于新增库包，不为本文预先实现 `kit/editor`、工具基类或插件管理器。
- 编辑历史属于文档修改记录，与玩法命令队列职责不同；不因为已有 `core/messaging` 就强制复用队列作为撤销系统。

## 9. 新工具的交付与验收

每个工具在项目文档或源码头部说明：编辑目标、状态所有者、输入与捕获方式、一次事务的范围、取消行为、修改入口、派生数据刷新以及保存结果。没有的能力如实标注，不把仅能绘制的工具描述为可完整编辑。

按实际能力验证以下行为；不适用项注明原因：

- 正常提交与无变化操作；连续多帧操作只有一条历史，多对象修改保持原子性。
- 取消、撤销、重做后，内容与派生结果正确；含堆数据的历史无别名污染和泄漏。
- 修改被拒绝、目标删除、句柄复用、切换工具或文档、离焦和关闭视口时安全结束。
- UI 不穿透，文本输入不触发场景快捷键；拖出视口后仍能松开或取消，不会同时触发相机或选择。
- 保存并重载内容一致；取消和撤销回保存状态后未保存标记正确，保存失败保留原文件和当前修改。
- 试玩与编辑文档相互独立；发布构建不可达编辑器及开发专用依赖。
- 视口、布局或输入换算变化时，在相关的偏移视口、resize、非整数缩放场景下检查最终画面与命中位置；按需单独检查字体和 3D 抗锯齿。只保存必要截图到 `library/screenshots/`。

事务与数据行为尽量用无窗口测试验证，真实输入、绘制和最终像素按本次改动直接运行工具验收；不默认添加自动交互或截图脚本。生成产物遵循 [目录纪律](new-project.md#生成文件与目录纪律)，目录、文档和配置调整不额外截图。同目录原子保存文件仍按保存事务管理。把已实现的检查接入项目的 `tools/check`，层间依赖规则按 dod-guidelines 第 2 节维护；不以编译成功替代交互或视觉验收。
